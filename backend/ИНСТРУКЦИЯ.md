# 🚀 Инструкция по запуску КыргызКомур API

## 📋 Быстрый старт

### 1. Установка зависимостей

```bash
cd backend
pip install -r requirements.txt
```

### 2. Настройка переменных окружения

Создайте файл `.env` на основе `.env.example`:

```bash
copy .env.example .env  # Windows
# cp .env.example .env  # Linux/Mac
```

Отредактируйте `.env` по необходимости (по умолчанию настройки подходят для разработки).

### 3. Запуск сервера

```bash
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

Сервер будет доступен по адресу: **http://localhost:8000**

API документация: **http://localhost:8000/docs**

## 👤 Создание первого администратора

### Способ 1: Интерактивный скрипт (рекомендуется)

```bash
python create_admin.py
```

Следуйте инструкциям на экране.

### Способ 2: Через аргументы командной строки

```bash
python create_admin.py "Имя пользователя" "email@example.com" "пароль123"
```

Пример:

```bash
python create_admin.py "admin" "admin@kyrgyzkomur.kg" "admin123"
```

### Способ 3: Вручную через Python

```python
from database import SessionLocal
from models import User

db = SessionLocal()
user = db.query(User).filter(User.email == "ваш@email.com").first()
user.role = "ADMIN"
db.commit()
db.close()
```

## ✅ Проверка работоспособности

### Автоматические тесты

Запустите тестовый скрипт для проверки всех функций:

```bash
python test_full.py
```

Этот скрипт проверит:
- ✅ Регистрацию пользователей
- ✅ Вход (login)
- ✅ Выход (logout)
- ✅ Проверку неправильного пароля
- ✅ Админ панель
- ✅ Защиту admin endpoints от обычных пользователей

### Ручное тестирование

#### Регистрация

```bash
curl -X POST http://localhost:8000/register \
  -H "Content-Type: application/json" \
  -d '{"username":"testuser","email":"test@example.com","password":"test123"}'
```

#### Вход

```bash
curl -X POST http://localhost:8000/login \
  -H "Content-Type: application/json" \
  -d '{"email":"test@example.com","password":"test123"}'
```

Ответ:
```json
{
  "token": "eyJhbGc...",
  "user": {
    "id": 1,
    "username": "testuser",
    "email": "test@example.com",
    "role": "USER",
    "created_at": "2024-01-01T00:00:00"
  }
}
```

#### Выход (logout)

```bash
curl -X POST http://localhost:8000/logout \
  -H "Authorization: Bearer ВАШ_ТОКЕН"
```

#### Админ панель

```bash
curl -X GET http://localhost:8000/admin/panel \
  -H "Authorization: Bearer ТОКЕН_АДМИНА"
```

## 🔐 Авторизация

API использует JWT (JSON Web Tokens) для авторизации.

### Получение токена

После успешного `/login` или `/register` вы получите токен в поле `token`.

### Использование токена

Добавьте токен в заголовок `Authorization`:

```
Authorization: Bearer ВАШ_ТОКЕН
```

Пример с curl:

```bash
curl -X GET http://localhost:8000/admin/panel \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

### Роли пользователей

- **USER** — обычный пользователь (по умолчанию при регистрации)
- **ADMIN** — администратор (полный доступ ко всем функциям)

## 🐛 Возможные проблемы

### ModuleNotFoundError: No module named 'jose'

**Решение**: Установите зависимости

```bash
pip install -r requirements.txt
```

### ModuleNotFoundError: No module named 'bcrypt'

**Решение**: Установите bcrypt

```bash
pip install bcrypt==4.1.2
```

### Port already in use (Порт уже используется)

**Решение**: Используйте другой порт

```bash
uvicorn main:app --reload --port 8001
```

### 401 Unauthorized при обращении к защищённым endpoints

**Причины**:
- Токен не передан
- Токен истёк (по умолчанию 24 часа)
- Неправильный формат токена

**Решение**: Получите новый токен через `/login`

### 403 Forbidden при обращении к /admin/*

**Причина**: У пользователя нет роли ADMIN

**Решение**: Измените роль пользователя на ADMIN (см. раздел "Создание первого администратора")

## 📝 Разработка

### Структура проекта

```
backend/
├── main.py              # Главный файл приложения
├── models.py            # Модели БД (User, Product, Vacancy)
├── schemas.py           # Pydantic схемы для валидации
├── database.py          # Подключение к БД
├── auth.py              # Авторизация и JWT
├── routers/
│   ├── auth_router.py       # /register, /login, /logout
│   ├── admin_router.py      # /admin/*
│   ├── products_router.py   # /products/*
│   └── vacancy_router.py    # /vacancy/*
├── requirements.txt     # Зависимости
├── .env                 # Переменные окружения
├── create_admin.py      # Скрипт создания админа
└── test_full.py         # Полный тест API
```

### Добавление нового endpoint

1. Создайте функцию в соответствующем роутере
2. Добавьте декоратор `@router.get/post/put/delete`
3. Укажите схемы запроса и ответа
4. Для защищённых endpoints добавьте `Depends(get_current_user)` или `Depends(require_admin)`

Пример:

```python
@router.get("/my-endpoint", response_model=MySchema)
def my_endpoint(
    db: Session = Depends(get_db),
    current_user: User = Depends(get_current_user)
):
    # Ваш код
    return result
```
